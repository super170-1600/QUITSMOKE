# NICØ · 共生星图（Symbiotic Constellation）
## 互助模块 UI/UX、业务规则与 Codex 分阶段实施规范 v1.0

> 状态：设计基线 / 可执行原型规范，**不是**对现有数据库、API 已实现能力的声明。  
> 与现有站点关系：封面 → 3D 封印晶体 Hub → 互助功能切面展开 → 共生星图。  
> 视觉优先级：**高级 CGI 材质、少文字、空间秩序** > 粒子数量与发光强度。  
> 范围：本期重点实现一核双轨场景、打卡反馈、鼓励特效、共同计划原型、目标纪念效果。**不设计求助信号**。

---

## 1. 产品定位与不可变约束

### 1.1 核心主张

互助不是以聊天记录为中心的通讯页，而是戒烟者与**最多两位支持者**共同参与、持续改变的一件 3D 艺术装置。行为具有空间反馈，但动画不替代真实的业务记录。**戒烟记录属于戒烟者；支持者提供陪伴与鼓励，不承担监管、判罚或代填责任。**

### 1.2 设计已确认事项

- 主页面采用可翻转的不规则六主面晶体，05 支持面打开共生星图；04 预留不启用。
- 星图采用**一核双轨**：中央戒烟核心，两个空间倾角不同的开放式支持轨道；支持者不足两位时只显示真实成员，不伪造人物。
- 主场景仅显示**当前聚焦的一个计划弧线**；其他计划按需展开，不叠加完整大环。
- 主要动作：**打卡、鼓励、共同计划、目标完成纪念**；保留现有聊天作为次级入口，但不把聊天框当主视觉。
- 鼓励有多种不同的粒子特效；日常打卡、关键无烟天数、计划完成采用**不同级别**的反馈。
- 页面文字极少，默认不出现宣传句、大标题、模块说明、传统侧栏；在表单、权限、数据口径和报错处必须保持清晰文字。
- 视觉延续首页：暖白场景、清透玻璃、银白结构、暖金高光、适量灰黑颗粒。拒绝过强 Bloom、紫蓝赛博风和磨砂白塑料感。

### 1.3 不在本阶段范围

- 求助信号、在线状态强制展示、排行榜、签到奖励货币、社交动态流、付费特效。
- 不能把吸烟一次表现成整个作品破碎或陪伴关系衰退。
- 不新增不存在的情绪/烟瘾共享权限、成就永久解锁、即时通讯推送成功等承诺。

## 2. 信息架构与状态层级

```text
Hub / 05 支持晶体面
  └─ 共生星图 / constellation
      ├─ 默认空间（Scene）
      │   ├─ 中央生命核心 → 今日打卡（真实现有功能）
      │   ├─ 支持者光核 A/B → 鼓励发送/接收 + 次级沟通
      │   ├─ 当前计划弧线 → 计划详情/创建/编辑
      │   └─ 纪念入口 → 历史纪念 / 事件回访
      ├─ 打卡浮层（CheckinSheet）
      ├─ 鼓励浮层（EncouragementComposer / Inbox）
      ├─ 计划浮层（PlanEditor / PlanDetail）
      └─ 纪念空间（RelicGallery）
```

**切面转场**：Hub 中的“互助”功能面前移，镜头穿过半透明平面，光线重组成两条开放轨道，中心浮现生命核心。返回时反向收束到原功能面。允许直接深链访问互助页面，不强制先播放 Hub 动画。

**角色**：戒烟者可以修改自己的打卡、提议/确认计划、查看授权共享的鼓励；支持者可以鼓励、建议计划并查看授权的状态，**不能为戒烟者打卡**。详细权限必须以现有后端规则为准。

## 3. 视觉结构（对应附图 01）

### 3.1 默认场景：一核双轨

| 元素 | 空间位置/造型 | 视觉与功能 | 约束 |
|---|---|---|---|
| 中央生命核心 | 原点附近，透明球状/分瓣玻璃雕塑，银白呼吸丝线 | 点击打开打卡；完成时脉冲 | **不再封印香烟**，与 Hub 的“封印香烟”形成叙事对照 |
| 支持轨道 A | 倾斜约 +25°，开放扭转曲线 | 支持者 A 的暖金小光核；鼓励粒子沿曲线抵达中心 | 倾角是调参初值，非固定 UI 规范 |
| 支持轨道 B | 倾斜约 -40°，深度偏移的开放曲线 | 支持者 B 的冷银偏暖小光核 | 不以位置、体积表达亲密程度高低 |
| 当前计划弧线 | 在双轨之外，细线分段/节点 | 点击展开计划细节；完成节点逐个激活 | 同屏最多 1 条高亮计划 |
| 纪念迹点 | 边缘仅 1–3 个微型晶体 | 点击进入纪念空间 | 不把历史事件全部堆进默认空间 |
| 气氛光子 | 稀疏的小粒子、短拖尾、温暖投影 | 空间深度与情绪层次 | 必须可以独立关闭/降密 |

**空间相机**：桌面默认轻俯视 3/4 角度，能够同时辨认中央核心、两个支持光核、前后错层；用户可缓慢拖拽观察，但旋转不得妨碍按钮点击。支持者只有一位时保留相对自然的单轨构图；没有支持者时出现**空轨提示及邀请入口**，不渲染虚假光核。

### 3.2 视觉层级与文字

主视觉优先：核心 > 两条轨道/光核 > 当前计划 > 稀疏粒子 > 信息标签。固定可见文字尽量仅有品牌角标、必要的短标签/状态与返回图标。对所有图形点击目标提供屏幕阅读器可访问名称；首次访问展示短暂“拖动查看 / 点击核心打卡”的交互教学，并允许关闭。

### 3.3 材质质量标准

- Blender 建模并导出 GLB 可用于核心与轨道重点资产；Three.js 负责相机、局部互动、GPU 粒子和 UI 叠层。
- 清澈光学玻璃优先于磨砂玻璃；避免使用单纯高 opacity 造成泛白。
- 环境光：大面积暖白柔光 + 窄条银蓝边缘光 + 局部暗部反射；高光应服务于切面和弧线形态。
- 具有真正前后穿插的空间曲线，不是屏幕二维圆环叠图；避免全部围绕圆心匀速公转。
- 背景采用暖白留白、轻阴影与极弱反射地面；移动端减少折射层数。

## 4. 鼓励系统：五种可辨认的粒子语言

**统一路径**：支持者选择光效 → 可选短留言 → 明确提交 → **后端确认成功** → 本地演出“发出”特效；戒烟者读取到真实鼓励时展示待查看光点并可重播。动画不等于发送成功。

| ID | 名称 | 形态 | 时长建议 | 控制重点 |
|---|---|---|---|---|
| `glow` | 微光 | 柔和暖金粒子从外轨缓慢汇入核心 | 1.8–2.6s | 最克制，低亮度 |
| `starlight` | 星雨 | 数条弧形银白短尾，大小疏密随机 | 2.0–3.0s | 不要全屏流星雨 |
| `resonance` | 共振 | 细透明球面波纹向核心传播 | 1.6–2.4s | 波纹轻、层数少 |
| `bloom` | 绽放 | 细薄玻璃瓣张开，带短促暖金微粒 | 2.4–3.4s | 保留核心可见性 |
| `halo` | 星环 | 局部银白点云组成非闭合环，短暂停留 | 2.0–3.2s | 不是巨大霓虹光圈 |

**交互**：光核点击后展示五个**动态预览缩略符号**，一个有清晰名称的精简选择浮层，可附短句。发送后仅在真正成功时出现已发送状态；失败保留输入内容并可重试。支持者并非必须拖拽，点击发送是可靠的等价途径。戒烟者点击未读光点可以重播；有多条消息时将事件整合为可访问的短列表，**不在 3D 中渲染海量粒子**。

**数据最小字段（仅为新功能提案）**：`id, family_id, sender_id, recipient_id, effect_type, text?, created_at, status/read_at?`。优先检查是否能复用现有鼓励消息/聊天表；如无法承载特效类型，先以本地 mock 协议做 UI，不得擅自改 schema 或伪装已同步。

## 5. 打卡反馈与时间节点

中央核心点击打开现有打卡流程，复用“日期、吸烟支数 0–200、烟瘾 1–5、备注 ≤300 字”等既有字段与校验。仅在**真实提交成功**后播放基础脉冲；失败不播放庆祝特效。

| 类型 | 触发依据 | 特效 | 记录规则 |
|---|---|---|---|
| 日常打卡 | 当天记录成功写入 | 核心呼吸脉冲 + 少量银粒回收，约 1.0s | **吸烟支数大于 0 也可以成功打卡**，不等于无烟庆祝 |
| 首日无烟 | 已有记录满足连续无烟 1 天 | 柔和第一道光弧 | 需真实零支记录 |
| 3 天 | 当前连续无烟 3 天 | 稳定内轨显形 | 不补齐缺失日 |
| 7 天 | 当前连续无烟 7 天 | 玻璃小环闭合 | 区分当前连续与历史最长 |
| 14 天 | 当前连续无烟 14 天 | 双层轻丝带短暂展开 | 仅在首次跨越或明确再次达成时避免重复轰炸 |
| 30 天 | 当前连续无烟 30 天 | 纪念晶体生成式演出 | 本期展示可先由既有阈值推导，不写入永久成就表 |
| 100 天 | 远期美术扩展 | 稍大型柔和光子簇 | 当前数据/里程碑支持情况待核实 |

**重要**：按日打卡与“连续无烟天数”是两回事；缺失日不能作为零支。补录、编辑、更正后应重新依据统计事实显示状态，不得自动重复授予不可撤销的永久纪念。连续记录中断时不破坏关系雕塑，不用视觉惩罚。

## 6. 共同计划系统

### 6.1 计划结构

- 戒烟者可创建/确认计划；支持者可提出建议、选择加入陪伴、在节点留下鼓励，不能替戒烟者判定完成。
- 默认场景只呈现**一个聚焦计划**。其他计划从计划弧线点击后进入精简列表/浮层。
- 支持一次性、连续与范围内累计目标，统一包含 `start_at/end_at, status, target, progress, participants, verification_mode`。

### 6.2 第一版计划类型

| 类型 | 示例 | 判定方式 | 特别边界 |
|---|---|---|---|
| 连续无烟 | 连续 7 天 0 支 | 根据已记录逐日零支计算 | 缺失记录不能通过 |
| 连续记录 | 连续 7 天提交记录 | 依据记录存在性 | 记录不要求 0 支 |
| 吸烟上限 | 未来一周 ≤10 支 | 完整日期覆盖 + 累计实际支数 | 未覆盖日期只能显示待确认 |
| 场景型 | 睡前不吸烟 | 戒烟者自主确认 | 现有每日打卡没有吸烟事件时刻，不能自动验证 |

**计划图形**：连续目标 → 分段节点弧线；累计目标 → 从透明到亮银的进度弧；行为目标 → 少量时间刻度与自主确认标记。节点已达成亮起，待验证为虚线/低亮，不要用虚假的进度填充。

### 6.3 生命周期（数据状态，不仅是动画）

`proposed → accepted → active → completed / missed / cancelled / expired`。定义提案发起人、谁能接受、修改后的版本、失效/取消原因。对于可自动核验目标，统计结果为权威；对于自主确认目标须显式显示“自主确认”。每次达到完成条件时，只有成功持久化的状态转移才能触发一次完成演出，防止重复奖励。

### 6.4 达成特效

- **Level 1 普通记录**：核心小脉冲，约 1s。
- **Level 2 无烟节点**：弧线局部闭合 + 稀疏银粒，约 2s。
- **Level 3 计划完成**：该计划弧线闭合 → 支持轨道短时响应 → 微型纪念晶体凝聚，约 3–4s。
- **Level 4 重要节点**：局部多层光丝与香槟金粒子交织，约 4s，提供跳过。

多位支持者无需同时在线，动画不应虚构实时同步；没有支持者时完成计划也必须给予正常视觉反馈。

## 7. 纪念与历史

- 默认仅展示最多 1–3 个近期纪念迹点，完整历史在独立的简洁“记忆空间”按需展开。
- 计划完成的纪念资产可按目标类型选择程序化变体：环形晶体（连续无烟）、多层棱晶（数量约束）、刻度银环（连续记录）、开放式玻璃雕塑（自主行为）。
- **首次开发只能承诺“可重建的视觉纪念”**：若尚无永久纪念数据模型，不宣称已经拥有永久解锁与历史达成时间。优先从真实事件历史推导，或经用户单独批准后增加持久化。
- 失败、吸烟、断签或计划取消不销毁用户已经真实获得的鼓励与关系历史；隐私/删除操作按真实产品规则处理。

## 8. 动画与交互状态机

```text
hubTransition → idle
idle → orbitInspect → idle
idle → checkinOpen → submitting → success / error → idle
idle → supporterFocused → effectPicker → composing → sending → sent / error → idle
idle → planFocused → editing → saving → active / error → idle
idle → gallery → relicFocused → gallery → idle
```

**原则**：禁用重复提交；所有动画均可取消；切路由、标签页隐藏、设备性能降级或用户开启 reduced-motion 时，必须立即进入稳定可用的 UI 状态。不能因为 WebGL 不可用而无法打卡、鼓励或管理计划。

## 9. 数据集成约束与风险

### 9.1 已知现有项目事实（来自既往只读审计，实施前需重新核实）

- Vue 3 + TypeScript + Vite + Vue Router + Pinia + Three.js，现有 ECharts/Vant 组件可复用。
- 已有打卡、家庭关系/身份、聊天与快捷鼓励、统计；支持者不可本人打卡。
- 现有前端连续无烟里程碑曾展示 1/3/7/14/30 天；永久成就表尚未核实有完整实现。
- CloudBase 分支的消息实时订阅曾未实现；**不能演出虚假的“在线已收到”效果**。可用轮询/手动刷新作为明确的 MVP 降级，但必须实际核实后端能力。
- 本文未检查仓库的最新实际代码；Codex 执行前须先审计对应文件，**不得凭文档假设存在对应 API**。

### 9.2 新计划与特效的持久化

共同计划与 effect_type 可能需要新数据模型。**本期先定义前端接口与 mock adapter**，验证 UI、动效和状态；经用户批准数据结构、角色权限与迁移方案后才接入生产数据库。禁止悄悄把这些数据塞进备注字符串或复用含义不匹配的列。

### 9.3 隐私权限

支持者仅看到被明确允许共享的信息；不要默认共享全部备注、烟瘾评分与私人记录。邀请/退出家庭、账号切换后清空角色 UI 缓存；现有后端权限/RLS 仍然是权威，3D 隐藏按钮不能取代鉴权。

## 10. 技术实施架构（建议，不强制文件名）

```text
src/views/ConstellationView.vue
src/components/constellation/{ConstellationCanvas,CheckinSheet,EncouragementPicker,
  EncouragementInbox,PlanEditor,PlanDetail,RelicGallery,AccessibleFallback}.vue
src/visuals/constellation/{scene,core,orbits,photons,effects,planArc,relics}.ts
src/config/{encouragementEffects,planTemplates}.ts
src/stores/constellationUI.ts          // 纯 UI 状态；不代替业务 store
src/services/constellationAdapter.ts   // 真实服务或明确标识的 mock
src/styles/constellation-tokens.css
```

引擎优先沿用现有 **Vue + Three.js + Blender/GLB**，不要引入 React Three Fiber。GLB 承担艺术资产，Three.js 负责互动对象位置和粒子生命周期，DOM/Vue 承担表单与无障碍。事件与动画解耦：业务数据更新触发“允许播放”的事件，动画永远不能决定业务成功与否。

**性能初始预算（目标，不是已测承诺）**：桌面优先 60FPS，移动端争取稳定 30FPS 以上；按设备限制 DPR、粒子数、透明层数；屏幕外暂停渲染，离开路由释放 GLB、贴图、事件与 RAF；每次迭代记录实际硬件测试帧率、draw calls 和内存占用。

## 11. 分阶段执行计划与验收门槛

### Phase S0 — 只读审计（必须先做）
- 核对 Hub 现状、05 功能面的路由、家庭模型（含支持者数量）、打卡权限、鼓励存储、统计公式、聊天与消息刷新逻辑。
- 输出：文件级可复用列表、支持者身份映射与风险、真正需要增加的数据表/API 清单。
- **零代码修改，等待确认**。

### Phase S1 — 高品质静态空间样板
- 独立预览路由，制作中央玻璃生命核心、两条开放支持轨道与 0/1/2 支持者三种排布、1 条示意计划弧及稀疏光子。
- 只用明确标识的**模拟数据**，不展示假在线/假用户。
- 分层开关：core、orbitA、orbitB、planArc、photons、relics；固定相机、交互视角与材质 A/B。
- 验收：1440×900 桌面截图、手机截图、3/4 角度视图、无/单/双支持者；光照/玻璃不泛白；界面无大段文字。

### Phase S2 — 鼓励特效样板
- 五种独立特效预览 + 发送/接收动画，时间轴可取消可重播；mock 数据闭环。
- 验收：五种效果的录屏/截图与视觉区别，重复触发/切页不会重影或泄漏粒子；reduced-motion 可用。

### Phase S3 — 计划与打卡联动样板
